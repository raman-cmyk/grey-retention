Every content schema is strict; links must be https/http/mailto without credentials and pictures https (or inline PNG/JPEG/GIF/WebP for previews), at most 2000 characters. `BlockBrand` carries the Step 0 roles (`name`, `site`, `logo`, `font`, `ink`, `background`, `accent`, `dark`, `radius`); `brandFromKit` picks roles from an unordered `brand_kits.colors` list by lightness and chroma. `renderEmail` re-validates every block (a stored block can never skip the schema), draws a white 600px container on the background with `bgcolor` for Outlook, stacks under 620px, gives one h1, ends with exactly one footer, and in `klaviyo` mode refuses inline pictures and writes the Step 0 footer tags (`{{ organization.name }}`, `{{ organization.full_address }}`, `{% unsubscribe "Unsubscribe" %}`, `{% manage_preferences "Preferences" %}`, `{% web_view "View in browser" %}`). All text is escaped including `{`, `}` and bidi controls.

- Ready buttons (2026-11-07): `SubmitButton` and the `ConfirmDialog` trigger stay disabled until the page is interactive (`components/ui/use-hydrated.ts`, `useSyncExternalStore`: false in the server HTML and during hydration, true in the browser). A click on a slow page before hydration used to post the form natively, so the page reloaded and its "saved" message was lost, or the dialog never opened. This was the first failure behind the mobile UC-09/12/16 browser runs. Playwright waits for a button to be enabled before it clicks, so the journeys no longer race hydration.
